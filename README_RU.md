# Motion Studio

Motion Studio — это производственный конвейер для коротких моушн-дизайн видео. Он берёт сырой бриф клиента и проводит его через 17 стадий с контрольными точками (исследование, концепция, сценарий, раскадровка, стиль, ассеты, анимация, озвучка, звук, музыка, монтаж, цветокоррекция, финишинг, QA и дистрибуция, публикация по расписанию), на выходе давая сданный мастер и набор нарезок под каждую социальную платформу.

Конвейер построен на:

- **[Remotion](https://www.remotion.dev/)** — для всего моушн-дизайна и рендеринга. Каждая сцена — React-композиция, управляемая через `useCurrentFrame()`.
- **[ElevenLabs](https://elevenlabs.io/)** — для синтеза голоса, клонирования голоса и дубляжа.
- **Навыки [Claude Code](https://claude.com/claude-code)**, которые выступают как «команда» специалистов. Каждая стадия — это навык, а навык-оркестратор (`ms-command`) выстраивает их по порядку и контролирует переходы.

> **Статус:** Репозиторий сейчас содержит только определения навыков (`.claude/skills/`). Проект Remotion, папки запусков и конфигурация создаются командой `/ms-setup` на чистой машине. См. раздел [Начало работы](#начало-работы).

## Как это работает

Запуск — это последовательность **стадий**. У каждой стадии есть один владеющий навык, она принимает артефакт предыдущей стадии и создаёт новый. Каждая стадия заканчивается **контрольной точкой (gate)**:

1. Артефакт представляется вместе с критериями прохождения/непрохождения и сравнением с предыдущей ревизией.
2. Продюсер либо **утверждает** (следующая стадия запускается сразу), либо **возвращает на доработку** с замечаниями (стадия перезапускается).
3. Ничто не переходит дальше непройденной контрольной точки.

Каждый артефакт записывается на диск и в реестр запуска, поэтому запуск можно приостановить, возобновить, разветвить для A/B-концепций или откатить к более ранней версии.

Голос бренда (`ms-brand-voice`) — это сквозная контрольная точка. Она проверяет каждый артефакт (сценарий, доски, стайлфреймы, сцены, монтаж, грейд, финишинг и тексты для дистрибуции) по зафиксированной рубрике голоса и списку запрещённых терминов.

## Справочник по навыкам

Каждый навык лежит в `.claude/skills/<name>/` и содержит точку входа `SKILL.md` и папку `references/` с подробными протоколами, схемами и рубриками. Навыки загружаются только тогда, когда активна их стадия.

| Навык | Назначение |
|---|---|
| `ms-command` | Оркестратор. Запускает стадии по порядку, соблюдает контрольные точки, сохраняет состояние запуска и хранит контракт на мастер-поставку. |
| `ms-setup` | Однократная настройка окружения: инструменты, учётные данные (сначала MCP, затем API-ключ), интервью для профиля студии и каркас проекта. |
| `ms-brand-voice` | Рубрика голоса бренда и проверка запрещённых терминов на всех стадиях. |
| От `ms-brief-intake` до `ms-video-editor`, `ms-color-grader`, `ms-finishing-suite`, `ms-quality-assurance`, `ms-social-distributor`, `ms-social-calendar` | Навыки стадий, как перечислено в таблице конвейера. |

Больше всего справочных материалов у `ms-command`: профили клиентов, пресеты, спецификации платформ, рубрика QA, схема состояния запуска, обработка сбоев и заметки по стеку Remotion и ElevenLabs. Начните с него, если хотите понять запуск от начала до конца.

## Начало работы

### Требования

- **Node.js 20+** и **npm 10+** (или pnpm)
- **Python 3.10+**
- **git** и **jq**
- **Claude Code** с открытым этим репозиторием, чтобы навыки из `.claude/skills/` были доступны
- Аккаунт **ElevenLabs** (через его MCP-сервер, если доступен, или по API-ключу)
- Опционально: учётные данные **AWS**, если рендер идёт через Remotion Lambda

### 1. Клонируйте репозиторий

```bash
git clone https://github.com/nikita-simankov/motion-stack.git
cd motion-stack
```

### 2. Запустите настройку

В Claude Code, из корня репозитория:

```
/ms-setup
```

Настройка проходит через следующие шаги:

1. Проверка или установка Node, npm, Python, git и jq.
2. Установка Remotion (`remotion`, `@remotion/cli`, `@remotion/lambda` и связанные пакеты) и Python SDK для ElevenLabs.
3. Получение учётных данных для каждого внешнего сервиса. Если подключён MCP-сервер, используется он; иначе API-ключ записывается в `.env`.
4. Интервью из 10 вопросов о профиле студии, которое записывает `runs/_studio.json`.
5. Создание каркаса проекта: `src/`, `remotion.config.ts`, `public/`, `out/`, `runs/` и `.gitignore`.
6. Проверка установки.

Настройку можно безопасно запускать повторно. Полезные варианты:

```
/ms-setup verify     # только проверка окружения
/ms-setup creds      # только получение учётных данных
/ms-setup interview  # повторно пройти интервью о профиле студии
/ms-setup upgrade    # обновить закреплённые зависимости
```

### 3. Проверка

```
/ms-setup verify
```

Каждая проверка должна показать `ok`. При сбоях выводится, какого инструмента, файла или учётных данных не хватает.

## Использование

### Запустить полное производство

```
/ms-command <бриф клиента>
```

Если бриф не передан, `ms-command` сначала проводит опросник для приёма брифа (см. `.claude/skills/ms-command/references/intake.md`).

### Управление запуском

| Команда | Что делает |
|---|---|
| `/ms-command resume <project-id>` | Продолжить с последней пройденной контрольной точки |
| `/ms-command status <project-id>` | Показать панель рендера |
| `/ms-command stage <skill-name>` | Запустить одну стадию изолированно |
| `/ms-command branch <stage>` | Разветвить запуск в контрольной точке для A/B-концепций |
| `/ms-command approve [n]` или `approve 4-7` | Пройти текущую контрольную точку или диапазон |
| `/ms-command revise <notes>` | Вернуть текущую контрольную точку на доработку с замечаниями |
| `/ms-command rollback <stage> <v>` | Откатить стадию к предыдущей версии |
| `/ms-command halt` | Заморозить запуск и сбросить реестр на диск |
| `/ms-command intake` | Только опросник для приёма брифа |

### Флаги

| Флаг | Эффект |
|---|---|
| `--auto` | Идти вперёд до первого отклонения или отмеченной контрольной точки |
| `--preset <name>` | Загрузить среду выполнения, набор платформ и тон из `references/presets.md` |
| `--client <profile>` | Загрузить голос клиента, палитру и лицензионные правила |
| `--quiet` | Скрывать таблицу контрольных точек, если она не изменилась |
| `--verbose` | Показывать промпты, вызовы инструментов и решения о маршрутизации |
| `--batch <file>` | Поставить в очередь несколько брифов и запускать их по порядку |
| `--render-local` / `--render-lambda` | Принудительно выполнить локальный или Lambda-рендер |
| `--stub` | Заменить навыки последующих стадий заглушками. Полезно для тестирования оркестратора изолированно. |

## Артефакты запусков

Каждое производство пишет в `runs/`:

| Путь | Содержимое |
|---|---|
| `runs/_studio.json` | Профиль студии из интервью настройки |
| `runs/_clients/` | Профили клиентов (голос, палитра, лицензионные правила) |
| `runs/_sfx/` | Библиотека звуковых эффектов, разложенная по категориям |
| `runs/_luts/` | Цветовые LUT |
| `runs/_mcp.json` | Разрешённые MCP-подключения (**в .gitignore**) |
| `runs/<id>/<stage>/v<n>.md` | Версионированные артефакты стадий |
| `runs/<id>/audio/raw/`, `audio/archive/` | Сгенерированное аудио (большое; в .gitignore) |
| `runs/<id>/previews/`, `deliverables/`, `distribution/` | Рендеры и результаты (в .gitignore) |

## Учётные данные и секреты

- Учётные данные получаются **сначала через MCP**. Если MCP-сервер сервиса подключён, Motion Studio использует его и никогда не запрашивает сырой ключ.
- Иначе API-ключ записывается в `.env` с правами `chmod 600`. **Никогда не коммитьте `.env`.** Он перечислен в `.gitignore`.
- `runs/_mcp.json` содержит разрешённые данные подключений и тоже находится в `.gitignore`.
- Чтобы требовать MCP-серверы и полностью отключить запасной вариант с API-ключом, запускайте настройку с флагом `--mcp-only`. В этом случае настройка завершится ошибкой, если у обязательного сервиса нет MCP-сервера.

## Технические правила

Эти правила фиксированы для каждой стадии. Оркестратор соблюдает их на контрольных точках.

- **Видео:** только Remotion. Композиции — это React-компоненты, зарегистрированные через `<Composition>` с явными `width`, `height`, `fps` и `durationInFrames`. Анимация управляется через `useCurrentFrame()`. CSS-переходы, CSS-анимации и классы анимации Tailwind запрещены. Рендер — через `npx remotion render` или `@remotion/lambda`.
- **Голос:** только ElevenLabs. Модели: `eleven_multilingual_v2` (максимальная стабильность, 29 языков), `eleven_flash_v2_5` (низкая задержка, 32 языка), `eleven_turbo_v2_5` (баланс, 32 языка). Клонирование — через Instant Voice Cloning. Дубляж — через Dubbing v2.

Подробности см. в `.claude/skills/ms-command/references/remotion-stack.md` и `elevenlabs-stack.md`.

## Устранение неполадок

| Симптом | Решение |
|---|---|
| `/ms-command` говорит, что навык не найден | Убедитесь, что Claude Code открыт в корне этого репозитория, чтобы загрузился `.claude/skills/`. |
| `verify` падает на `src/Root.tsx` или `remotion.config.ts` | Запустите `/ms-setup scaffold`. |
| ElevenLabs не настроен | Подключите его MCP-сервер или запустите `/ms-setup creds --api-key-only`. |
| Стадия постоянно не проходит проверку голоса бренда | Посмотрите совпадения с запрещёнными терминами в `ms-brand-voice/references/banned-terms.md` и верните на доработку с замечаниями. |
| Потеряно состояние запуска | `/ms-command status <project-id>`. Запуски сохраняются в `runs/<id>/`. |
